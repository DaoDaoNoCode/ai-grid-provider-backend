# Draft fixtures: fixtures/draft/default

The data the draft fake (`internal/fakeinfra/draft`, served by `cmd/ai-grid-fake-infra`)
loads at start from `fixtures/draft/default/`, the default of `--draft-fixtures` and what
`make dev-fake` passes. This page was the console's `mock/fixtures/README.md` at `ac80c25`;
`fixtures/draft/README.md` says how the files came here. Every name, id, host and number is fictional. What the fake does with
each area's data is in `docs/draft/areas/`.

| File | Shape | Notes |
|---|---|---|
| `managedclusters.json` | `{"clusters": [ai_grid.v1.ManagedCluster...]}` in protojson | Full hub objects: the labels ACM and OCM write (`name`, `cloud`, `vendor`, `clusterID`, `openshiftVersion*`, `cluster.open-cluster-management.io/clusterset=default`, `feature.open-cluster-management.io/addon-*`) plus the console's `ai-grid/*` labels and annotations, `uid`, `resourceVersion`, `creationTimestamp`, finalizers, taints, client configs, and a `status` with every condition's exact type, reason and message, name-sorted claims (a `region` claim only on the AWS and Azure clusters), capacity (`nvidia.com/gpu` on GPU clusters) and version. Every state the ACM console distinguishes at least once, `AVAILABLE` three times and none `UNSPECIFIED` (every cluster has conditions): `local-cluster` (the hub, ten add-ons including `submariner`), `site-paris-1`, `site-frankfurt-1` ready (Paris enrolled with GPUs; Frankfurt not enrolled, no `ai-grid/*` labels, add-on `application-manager` `unhealthy`); `site-madrid-1` unknown (lease expired, taint `unreachable`, add-ons `unreachable`); `site-ashburn-1` offline (API server down, taint `unavailable`; its add-ons stay `available`, because the hub's add-on health check acts only on a lost lease); `site-berlin-1` importing and `site-oslo-1` pending import (`auto-detect` labels, no claims); `site-dublin-1` import failed; `site-lisbon-1` not accepted (`hubAcceptsClient: false`, `HubClusterAdminDenied`, add-ons `unreachable`); `edge-lyon-2` detaching (`deletionTimestamp`, `Deleting=False/ResourceRemaining` with the hub's garbage-collector message, "The resource managedclusteraddons is remaning, the remaining count is 7, the finalizer pending count is 1", upstream's spelling). `status.state` and `status.stateMessage` are derived by the server on every read and must not be written here. |
| `tenants.json` | `{"tenants": [ai_grid.v1.Tenant...]}` in protojson | Keycloak 26.8 Organizations as the backend maps them: UUID `id`, unique `name` and `alias` (alias defaults to the name and never changes), `enabled`, `description`, `attributes` (first value per key), `domains` as the lower-case names of `domainDetails`, each with `verified`, `identityProviderAlias`, `autoRedirect`, and an optional `resourceVersion` (a positive integer, default `1`: the version the backend keeps in the organization attribute `ai-grid/resource-version`, which must not appear in `attributes`; `docs/draft/areas/tenants.md`, "Version"). Six fictional organizations: one disabled (`umbrella-biotech`), one with two domains and attributes (`acme-robotics`), one with a wildcard domain (`vandelay-industries`), one without domains (`initech-labs`), one whose alias differs from its name (`globex-research` / `globex`), and `wayne-aerospace` with one verified domain. `acme-robotics`, `globex-research` and `initech-labs` carry an `identityProvider` (proposal P1, an OIDC client on a fictional `example.com` issuer); the fake checks it with the PoC's rules at start. The fake validates the file like Keycloak would (duplicate name, alias or domain, bad domain, non-v4-UUID id fail at start). No domain may set `identityProviderAlias`: the fake realm has no identity providers, so the fake refuses to start, as Keycloak refuses an unknown alias ("Identity provider with alias '<alias>' does not exist in realm ai-grid"). Other modes, one at a time: `{"unavailable": "<text>"}` makes every Tenants RPC that passes the token checks `Unavailable` (message `Keycloak is unavailable: <text>`, which the BFF turns into its generic 503 text; the shipped backend still returns `Unknown` here; a viewer's write stays `PermissionDenied` and an expired token `Unauthenticated`), `{"realmMissing": true}` makes them `FailedPrecondition` with `Keycloak realm "ai-grid": Realm not found.` (the dev hub today), `{"organizationsDisabled": true}` the same with `Organizations not enabled for this realm.`. |
| `models.json` | `{"models": [ai_grid.v1.Model...], "bindings": {"<namespace>": ["global"]}}` in protojson | The subset of a KServe `LLMInferenceService` the console writes, shaped like the hub instance (`baseRefs`, `model.uri/name`, `replicas`, the `openshift-ingress/openshift-ai-inference` Gateway, a managed route and the scheduler, a `main` container with resources and env), with `openshift.io/display-name|description` annotations, plus an optional `placement` (an ACM Placement: cluster sets, label selector, tolerations) and `rollout` (strategy, concurrency, deadline). `status` is derived on every read and must not be written here. Five fictional models in `ai-grid-models`: `tiny-llm` Ready on the hub; `granite-8b-instruct` placed on the enrolled and provisioned sites with the rollout complete (`site-paris-1` at start, `site-madrid-1` joins when its lease recovers at 300 s); `mistral-7b-instruct`, a Progressive rollout one OpenShift spoke at a time in cluster-name order, without `creationTimestamp` so it is created when the fake starts and can be watched live (`site-frankfurt-1`, `site-berlin-1` once it joins, `site-paris-1`, and `site-madrid-1` once its lease recovers); `llama-3-70b` failed on a preset the hub lacks (`ConfigNotFound` with KServe's exact message); `codellama-13b`, whose placement selects no cluster (`NoManagedClusterMatched`, `PlacementDecisionEmpty`). `bindings` names the ManagedClusterSets bound into a model namespace (`global` when not listed; an empty list is a namespace without a binding, `NoManagedClusterSetBindings`). The generated ManifestWorks are named `model-<name>` plus five random characters with no separator, the base cut to 58 characters (`model-mistral-7b-instructx7k2p`), as the API server's `generateName` does. A cluster labelled `ai-grid-mock/fail-apply=true` (a mock-only switch) fails to apply its work as a spoke without the KServe CRD would: the model manifest `Applied=False/AppliedManifestFailed` "Failed to apply manifest: the server doesn't have a resource type "LLMInferenceService"", the work `Applied=False/AppliedManifestWorkFailed` "Failed to apply manifest work", and `Available=Unknown` (`IncompleteResourceMeta` on the manifest, `ResourcesStatusUnknown` "1 of 2 resources have unknown status" on the work). |
| `subscriptions.json` | `{"subscriptions": [ai_grid.v1.Subscription...], "authPolicies": [...]}` in protojson | MaaS subscriptions and the authorization policies paired with them. No phase is stored: the fake derives it from the models, the policies and the clock. `engineering` (granite, Active), `data-science` (granite and the missing `retired-llm`, Degraded), `research` (`retired-llm` only, Failed) and `onboarding` (`tiny-llm`, no `createTime`, so it plays no phase, then Degraded, then Active live and has no auth policy). Fixture policies are unmanaged: they exist before the fake starts and are never deleted with a subscription. The PoC's version of this data is in `fixtures/draft/poc/`. |
| `presets.json` | `{"namespace", "presets": [...]}` | The `LLMInferenceServiceConfig` presets installed in the RHOAI applications namespace (`v3-6-0-kserve-config-llm-*`, the subset the research names), which `baseRefs` resolve against; an unknown one is accepted by the API server and fails later with `PresetsCombined=False/ConfigNotFound`, as on the hub. |
| `scenarios.json` | `{"events": [{"cluster", "at", "event", ...}]}` | Timed cluster transitions relative to the fake's start, in scenario time (`at`, a Go duration, divided by `speed` in `settings.json` for wall-clock time). The events and what each one changes are in `internal/fakeinfra/draft/scenarios.go`; `docs/draft/areas/clusters.md` lists the shipped ones. |
| `access.json` | who is a provider admin | Drives the fake hub's access review **and** the fake backend's answer to a mutating RPC: a token in `deniedTokens` (or any token when `defaultAllowed` is false) gets `PermissionDenied` with the API server's forbidden message from `UpdateManagedCluster` and with "is not a provider admin" from `CreateTenant`, `UpdateTenant`, `DeleteTenant`, `CreateModel`, `UpdateModel` and `DeleteModel`, a token in `rejectedTokens` gets `Unauthenticated` from every RPC, reads included, like an expired OpenShift token at the hub; so `AUTH_TOKEN=viewer-token` sees clusters, tenants and models but cannot enrol a cluster, create a tenant or deploy a model (the BFF answers 403, also for a PATCH that would change nothing; only a PATCH whose body names no field never reaches the RPC and is 200) and `AUTH_TOKEN=expired-token` sees nothing but the signed-out path. |
| `settings.json` | latency, speed, hub capabilities | `latency` is a Go duration such as `"40ms"` added to every RPC; a hub list from a pod on the hub takes tens of milliseconds. `speed` multiplies the scenario clock and the model lifecycles (`10` plays the five-minute scenario in 30 seconds; default `1`). `manifestWorkReplicaSetEnabled` (default true) is what `GetHubCapabilities` reports and what gates a placed model; `false` mirrors the dev hub, where the CRD exists but nothing reconciles it, so `CreateModel` with a placement, and an `UpdateModel` that adds one, are `FailedPrecondition` (412 from the BFF) and a seeded placed model keeps its decisions but an empty MWRS status (no works, `pending`). `observabilityInstalled` and `acmVersion` are reported as-is. |

Fixtures are protojson so they use the field names grpcurl shows and fail to load on any
unknown field; a fixture that fails to load stops the fake with an error, so a typo never
serves nonsense. A missing file leaves its part empty (no clusters, tenants, models or events)
or at its default: without `presets.json` four built-in presets (`v3-6-0-kserve-config-llm-template`,
`v3-6-0-kserve-config-llm-scheduler`, `v3-6-0-kserve-config-llm-router-route` and
`v3-6-0-kserve-config-llm-template-cpu`), without `settings.json` no latency, speed 1,
the gate on, observability off and ACM `2.17.3`, and without `access.json` every token is a
provider admin. A model namespace that `bindings` does not list gets `global`. The directory
itself must exist. Tests load the shipped directory
and check the ACM labels, that every condition uses only a type, reason and message the
research verified, that claims are sorted, that hub taints match the Available condition, that
each cluster derives the state it was seeded for, that the tenants are a realm Keycloak would
accept and cover the shapes listed above, and that every model uses only installed presets
(but the one seeded to fail), the product-default Gateway names
(`openshift-ingress/openshift-ai-inference`, `openshift-ingress/maas-default-gateway`), the
selector and toleration operators, the
built-in cluster sets and the rollout strategies, and derives the phase it was seeded for.
`ai-grid-provider-console/bff/internal/examples` compares the BFF's responses for the shipped fixtures with the golden
files in `ai-grid-provider-console/mock/examples/`, so a fixture change shows up there too (`make -C bff golden` rewrites
them; see `docs/draft/AGENTS.md`).
Fixture names, labels and ids must never be real: this repository is public. The
addresses the fake derives are synthetic too: external URLs under `example.com` and
internal ones as standard Kubernetes service names (`<svc>.<ns>.svc.cluster.local`) built
from the fictional Gateway names.
